## Detailed Findings

### F1. HIGH — Shell injection via eval'd output

**Files**: `src/cli/shell.rs:7-119`, `src/cli/env_cmd.rs:99`

Two injection vectors:
1. **`print_shell_init`**: Escapes single quotes but interpolates into *double-quoted* shell strings where `$`, backticks, `\`, and `!` are active. `DEN_HOME='$(malicious)' eval "$(den init)"` would execute the command.
2. **`print_env_switch_commands`**: No escaping at all. `den_home.display()` and `new_env.display()` are interpolated directly into export statements and sed expressions that get `eval`'d.

The attack requires either (a) a malicious `DEN_HOME` env var, or (b) a malicious environment path name (via `den env create`). Both are user-controlled, so this is not remotely exploitable, but it violates defense-in-depth for eval'd code.

**Fix**: Restrict environment path characters in `normalise_env_path` to `[a-zA-Z0-9._-]` (fixes F2 simultaneously). For `DEN_HOME`, switch to single-quoted strings in shell output.

---

### F2. HIGH — normalise_env_path allows unsafe characters

**File**: `src/cli/env_cmd.rs:184-199`

Only rejects `..`. Allows `$`, backticks, spaces, newlines, colons, null bytes — all problematic for shell interpolation and/or filesystem paths.

**Fix**: Validate each path component against `[a-zA-Z0-9._-]+`.

---

### F3. HIGH — Unvalidated formula_name in link/record functions

**Files**: `src/link/mod.rs:30-37,127-154`

`link_keg` creates `opt_dir.join(formula_name)` and `record_linked_version` writes to `.den/linked/{formula_name}`. While `install_formula` validates names via `validate_formula_name`, `env::materialise` reads names from the manifest JSON (user-writable) and passes them to `link_keg` without re-validation. A crafted manifest entry like `../bin/evil` could create symlinks outside the opt directory.

**Fix**: Add `validate_formula_name` as a precondition in `link_keg` and `record_linked_version`.

---

### F4. HIGH — cask module ungated for macOS

**Files**: `src/lib.rs`, `src/cask/mod.rs`, `src/cli/install.rs:283`

`cask` uses `hdiutil` and `/Applications` — macOS-only. Declared as `pub mod cask` without `#[cfg(target_os = "macos")]`. Will fail at runtime on Linux.

**Fix**: Gate `pub mod cask` in lib.rs behind `#[cfg(target_os = "macos")]`. Add runtime guard in `install --cask` CLI handler.

---

### F5. MEDIUM — XML injection in launchd plist

**File**: `src/daemon/mod.rs:476-504`

`launchd_plist` interpolates `den_binary.display()` and `den_home.display()` into XML via `format!`. Paths containing `<`, `>`, `&` would produce malformed plist or inject XML elements.

**Fix**: XML-escape interpolated values (`&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`).

---

### F6. MEDIUM — download_cask ignores client parameter

**File**: `src/cask/mod.rs:129`

Signature is `download_cask(_client: &Client, ...)` but builds its own HTTPS-only client internally. Caller's timeout/proxy/CA config is silently discarded.

**Fix**: Remove the parameter or use it as the base client.

---

### F7. MEDIUM — daemon_cmd.rs launchd calls ungated

**File**: `src/cli/daemon_cmd.rs:91-133`

`DaemonCommand::Install` and `Uninstall` use `launchctl` and `~/Library/LaunchAgents/` without cfg guards.

**Fix**: Gate behind `#[cfg(target_os = "macos")]` with a non-macOS fallback error.

---

### F8. MEDIUM — ZIP symlink attack window

**File**: `src/cask/mod.rs:289-308`

`unzip` extracts files (including symlinks) before the post-extraction validation runs. A malicious ZIP with `evil -> /tmp` followed by `evil/payload` writes through the symlink before the walkdir check catches it.

**Fix**: Use `WalkDir::new(dir).follow_links(false)` in the post-check, or switch to a Rust ZIP library for entry-by-entry validation.

---

### F9. MEDIUM — Non-atomic writes in 5 remaining locations

**Files**: `src/tab/mod.rs:79`, `src/env/mod.rs:90`, `src/link/mod.rs:134`, `src/bottle/mod.rs:48`, `src/api/mod.rs:44,54`

These use `std::fs::write()` while manifest, settings, and daemon state use `NamedTempFile::persist()`.

**Fix**: Apply the same atomic write pattern for consistency.

---

### F10. MEDIUM — Daemon doesn't handle SIGTERM

**File**: `src/daemon/mod.rs:248`

`ctrlc` only handles SIGINT. `den daemon stop` sends SIGTERM. launchctl sends SIGTERM. Both cause ungraceful shutdown.

**Fix**: Use `tokio::signal::unix::signal(SignalKind::terminate())` or `signal_hook`.

---

### F11. MEDIUM — ghcr_path allows path traversal

**File**: `src/formula/mod.rs:85-87`

`ghcr_path` converts `@` to `/` but doesn't validate against `..` or leading `/`. A crafted formula name could reference unintended GHCR repositories.

**Fix**: Validate output contains no `..` and doesn't start with `/`.

---

### F12. MEDIUM — Formula index download unbounded

**File**: `src/api/mod.rs:95-107`

No `MAX_DOWNLOAD_SIZE` check like bottles/casks have. A compromised CDN could serve an arbitrarily large response.

**Fix**: Add a size limit (e.g., 500 MB).

---

### F13. MEDIUM — CLAUDE.md crate structure outdated

Lists `tap/` and `download/` (both empty directories). Missing `cli/` sub-modules.

**Fix**: Update the diagram.

---

### F14. MEDIUM — README missing CONTRIBUTING/SECURITY links

**Fix**: Add a Contributing section with links.
